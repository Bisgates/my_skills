# Manual authoring checks

## Scenarios
- “Grill me about my app idea; questions in a file.” → Discover existing facts; write the whole independent frontier to wave-1.md, open it, wait for explicit completion.
- “Wave 1 answered.” → Read saved answers; preserve them; ask only newly unlocked or necessary unresolved questions in wave-2.md. Blank is not consent.
- “Wave 3 answered; continue implementing the agreed draft.” → Summarize, no fourth questionnaire. Apply execution authorization separately. “You may ask one more wave” explicitly permits wave 4 only.

## Trigger checks
Should trigger: /grill-me; use grilling on this design; stress-test this plan with a question interview; interview me in waves; resume wave 2 of our grilling interview.
Should not trigger: explain a design term; fix this bug; open an existing Markdown note; compare two models factually; summarize a finished interview without new questions.

## Checks
- Each wave is one editable Markdown file with recommendations and blank Answer fields.
- Dependent questions wait for prerequisite answers; already known decisions are not re-asked.
- Editing without a completion message does not advance the interview.
- Existing files and user answers survive a resumed session.
- Opening failures yield a file link and an honest status.
- At most three waves absent explicit extension; a broad request to continue does not bypass the cap.
